# Feature Specification: Notes 条件付き上書き・削除

**Feature Branch**: `docs/adr-0007-notes-overwrite-delete`

**Created**: 2026-08-11

**Status**: Draft

**Input**: User description: "write_note.js に、既存ノートの本文を安全に書き換える機能を追加する。ADR 0007(docs/adr/0007-conditional-overwrite-delete-for-notes.md)で承認済みの決定を実装する。背景: write_note.js は現在、ノートの作成・追記・境界付き部分置換(--replace-block)しかできず、本文全体の置換やノート削除ができない(意図的な設計)。この制約により、既存の自由記述(ユーザー自身が書いた内容も含む)を改善・訂正したい場合、末尾への追記しかできず、訂正が積み重なると読みにくくなる。必要な機能: 1) --overwrite-stdin(全文置換)2) --delete(削除)3) どちらも --expect-hash <sha256> を必須にする楽観的排他制御 4) --delete のNotes.app「最近削除した項目」相当での回収可否を実機で検証しSKILL.mdに記録 5) apple-notes SKILL.md / apple-notes-operator に実行前の利用者承認を運用規約として明記 6) CLAUDE.md「破壊的操作」節の更新。対象外: Remindersの削除機能、project_registry.py の追記専用運用(ADR 0006)。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 既存の自由記述を訂正する (Priority: P1)

利用者(またはその代理として動くエージェント)が、Notes内の既存ノート(利用者自身が書いたものを含む)の内容を、追記の連鎖ではなく、その場で正しい内容に書き換えたい。

**Why this priority**: これが今回の変更の直接の動機であり、これができなければ機能追加の価値がない。ADR 0007がすでに承認済み。

**Independent Test**: 既存ノートの本文を読み、そのplaintextのSHA-256を計算し、新しい本文と共に `--overwrite-stdin --expect-hash <hash>` を呼ぶ。ノートを読み直し、本文が新しい内容だけになっている(訂正の追記が残っていない)ことを確認できる。

**Acceptance Scenarios**:

1. **Given** 既存ノートの現在の本文とそのSHA-256ハッシュが分かっている、**When** そのハッシュと新しい本文で `--overwrite-stdin` を呼ぶ、**Then** ノートの本文が新しい内容に置き換わり、それ以外のノートには影響しない。
2. **Given** ノートの本文がすでに変わっている(直前に取得したハッシュと現在のハッシュが一致しない)、**When** 古いハッシュのまま `--overwrite-stdin` を呼ぶ、**Then** 書き込みは一切行われず、ハッシュ不一致を理由にエラー終了する。

---

### User Story 2 - 不要になったノートを削除する (Priority: P2)

利用者が、不要になったノートをNotes.appを開かずに削除したい。削除が本当に元に戻せないのか、一定期間は回収できるのかを、推測ではなく確認した上で使いたい。

**Why this priority**: ADR 0007のスコープに含まれる2つ目の能力だが、上書きより発生頻度は低いと想定されるためP2。

**Independent Test**: テスト用に作成した使い捨てノートに対して `--delete --expect-hash <hash>` を呼び、通常の一覧から消えることを確認する。あわせて、Notes.appの「最近削除した項目」相当の場所を確認し、回収可能かどうかを実地で確認できる。

**Acceptance Scenarios**:

1. **Given** 既存ノートの現在の本文のハッシュが分かっている、**When** 正しいハッシュで `--delete` を呼ぶ、**Then** そのノートは通常の一覧・フォルダから消える。
2. **Given** ノートの本文がすでに変わっている、**When** 古いハッシュのまま `--delete` を呼ぶ、**Then** 削除は行われず、ハッシュ不一致を理由にエラー終了する。

---

### User Story 3 - 実行前に利用者の承認を得る運用に揃える (Priority: P3)

このリポジトリ内でNotesを操作するエージェント(`apple-notes-operator`)が、`--overwrite-stdin`/`--delete` を呼ぶ前に、置き換える内容・削除対象を利用者に提示し、明示的な承認を得てから実行する、という運用規約に従う。

**Why this priority**: コードでは強制できない合意ベースの安全策であり、ADR 0007が明記している前提。P1・P2の技術的な安全策(ハッシュ照合)を補完する運用面の対策で、ドキュメント更新が中心。

**Independent Test**: `apple-notes` SKILL.mdと`apple-notes-operator`の説明文を読み、`--overwrite-stdin`/`--delete`を呼ぶ前に利用者承認を得る旨が明記されていることを確認できる。

**Acceptance Scenarios**:

1. **Given** `apple-notes` SKILL.mdを読む、**When** `--overwrite-stdin`/`--delete`の説明を探す、**Then** 実行前に置き換え後の内容(または削除対象)を利用者に提示し承認を得る、という運用規約が明記されている。

---

### Edge Cases

- `--expect-hash` を渡さずに `--overwrite-stdin`/`--delete` を呼んだ場合、書き込み前にエラーで停止する(必須引数の欠落として拒否)。
- 対象ノートが `--id` で解決できない(存在しない・削除済みなど)場合、ハッシュ計算自体ができないため、既存の `--id` 解決ルールに従いエラーで停止する。
- `--overwrite-stdin` に空の標準入力を渡した場合、本文を空にする書き込みとして扱う(空文字列も「新しい本文」として有効)。
- `--replace-block` の対象ブロックを含むノートに対して `--overwrite-stdin` を呼んだ場合、ブロックの内容ごと通常の本文置換の対象になる(フェンスは特別扱いしない — 全文置換なので当然ブロックも書き換わる)。
- 同じノートに対して並行して複数の書き込みが飛んできた場合、後から書き込まれた側は、先に書き込まれた側が変えた本文をハッシュ不一致として検出し拒否する(楽観的排他制御の想定通りの挙動)。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `write_note.js` は `--overwrite-stdin` オプションをサポートし、標準入力から渡されたテキストで既存ノートの本文全体を置き換えられなければならない。
- **FR-002**: `write_note.js` は `--delete` オプションをサポートし、既存ノートを削除できなければならない。
- **FR-003**: `--overwrite-stdin` と `--delete` は、どちらも `--expect-hash <sha256>` を必須の引数として要求しなければならない。
- **FR-004**: `--overwrite-stdin`/`--delete` の実行時、書き込み・削除の直前にシステムは対象ノートの現在の本文(plaintextとして取得したもの)のSHA-256を計算し、`--expect-hash` の値と一致する場合にのみ操作を実行しなければならない。
- **FR-005**: ハッシュが一致しない場合、システムは対象ノートに一切の変更を加えず、非ゼロ終了コードとハッシュ不一致を示すメッセージで停止しなければならない。
- **FR-006**: `--expect-hash` が省略された場合、システムは操作を実行せず、必須引数の欠落としてエラー終了しなければならない。
- **FR-007**: `--overwrite-stdin`/`--delete` は、`--id` で指定された対象ノート以外のいかなるノートも変更してはならない。
- **FR-008**: システムは、削除されたノートがNotes.appの「最近削除した項目」相当の場所で一定期間回収可能かどうかを実機で検証し、その結果(回収可能/不可能、可能な場合は保持期間)を `apple-notes` スキルのドキュメントに事実として記録しなければならない。検証されていない挙動を安全であるかのように記載してはならない。
- **FR-009**: `apple-notes` スキルのドキュメントおよび `apple-notes-operator` サブエージェントの説明は、`--overwrite-stdin`/`--delete` を呼び出す前に、置き換える内容または削除対象を利用者に提示し、明示的な承認を得ることを運用規約として明記しなければならない。
- **FR-010**: `CLAUDE.md` の「破壊的操作」節は、Notes側の全文上書き・削除がもはや構造的に不可能ではなくなった実態を反映するよう更新されなければならない。Reminders側の削除が引き続き不可能であることは変更してはならない。
- **FR-011**: 本機能は `write_note.js --replace-block` の既存の挙動を変更してはならない。
- **FR-012**: 本機能は `project_registry.py` および、プロジェクトレジストリノートの追記専用運用([ADR 0006](../../docs/adr/0006-project-registry-as-notes-event-log.md))を変更してはならない。

### Key Entities *(include if feature involves data)*

- **Note**: Notes.app内の1件のノート。`id`(不透明なハンドル)と `body`(HTML、`--plaintext` で読める平文表現)を持つ。本機能では、この `body` の平文表現に対してSHA-256を計算する対象になる。
- **Expected hash**: 呼び出し元が直前に読んだノート本文(plaintext)のSHA-256。書き込み実行可否を決める比較対象であり、ノート自体には保存されない、呼び出しごとの一時的な値。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は既存ノートの内容を、訂正の追記が連鎖する形ではなく、その場で書き換えられた1つの現在値として読めるようになる(書き換え後にノートを読み、訂正前の内容が残っていないことで確認できる)。
- **SC-002**: 直前に読んだ内容と現在の内容が食い違っている状態での上書き・削除の試行は、100%の確率でデータを変更せずに拒否される。
- **SC-003**: 削除されたノートの回収可否は、本機能の完了報告前に「検証済みの事実」として文書化されている(推測や未検証の主張ではない)。
- **SC-004**: 既存の決定的テストスイート(`tests/run-*.sh`)は、本機能の追加後も無修正で全て成功する — 既存の作成・追記・`--replace-block`・プロジェクトレジストリ解決のいずれの挙動も退行しない。

## Assumptions

- 実機検証(削除の回収可否、ライブでの上書き・削除呼び出し)には、macOSとNotesへのAutomation許可が必要という、このリポジトリの既存の制約がそのまま適用される。決定的テストスイートはmacOSを必要としない設計を維持する。
- ハッシュの比較対象は生のHTML本文ではなく、`--plaintext` として読める平文表現とする — 利用者やエージェントが「読んだ」と認識する内容と、比較対象を一致させるため。
- 本機能は既存のアカウント・フォルダのid解決の仕組みをそのまま使う。新しいフォルダ・アカウントのスコープは導入しない。
- Reminders側(`remind-cli`)への削除機能追加は本フィーチャーのスコープ外(別の判断が必要な変更として切り離す)。
- プロジェクトレジストリノート自体に対して `--overwrite-stdin`/`--delete` を実際に使うかどうかは、本フィーチャーの範囲外の将来の判断とする — 技術的に可能になることと、実際にその運用を変えることは別。
